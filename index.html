💡 Basic Rules for JSON Syntax

These are strict rules for editing VS Code's settings.json. Please follow them carefully to prevent errors.

1. Enclose Keys and Values in Double Quotes

In JSON, keys (the name on the left) and string values (the content on the right) must always be enclosed in double quotes ". Single quotes ' cannot be used.

✔ Correct Example:
"sideBar.background": "#000000"
✖ Incorrect Example (Causes an error):
sideBar.background: #000000

2. Punctuation Rules

  • Between key and value: Separate with a colon :.
  • Between items: Separate with a comma ,.
  • At the very end: Do not place a comma after the final item (this is a major cause of syntax errors).

3. Data Type Differences

If a value is a "string", it must be enclosed in "...". However, numbers and booleans should not be enclosed.

Type Example Description
String "red" / "#ff0000" Must be enclosed in ""
Number 12 No "" needed
Boolean true / false No "" needed

4. The Role of "default"

Writing "default" as a value has the exact same effect as deleting the entire line: it reverts the setting to the original color of your currently installed theme.

The main reason to explicitly write "default" is to keep the setting name (key) in your file. This is useful when you don't want to override the color right now, but want to keep the setting available for future edits.

⚠️ Common Error Checklist

  • Did you forget to close any "?
  • Is there an extra , after the very last item?
  • Are you using ' (single quotes) instead of double quotes?

1. Fine-tune Specific Workbench Colors

If you want to build upon an existing theme but only change specific colors (such as the sidebar background or active tab), add workbench.colorCustomizations to your settings.json file. 

"workbench.colorCustomizations": {
    "sideBar.background": "#1e1e2e",
    "activityBar.background": "#11111b"
}

When exporting, you can use this snippet directly in your workbench settings, or output it as a complete JSON theme to use as a standalone theme file.
