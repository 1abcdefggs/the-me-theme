Engine Render Benchmark  EMod32 / Power-of-2 Alpha

Mod 32 Boundary + Power-of-2 Alpha vs. Conventional (Arbitrary) Color

This measures the speed difference when Chromium's Skia rendering engine (= VS Code's internal engine) renders an overlay using "hardware-optimized (Mod32 boundary, power-of-2 alpha)" colors versus "arbitrary (unoptimized)" colors. It triggers blending via the Canvas 2D API's globalAlpha / fillStyle, measuring the pure engine processing speed in milliseconds.

⚠�E�EMeasurement Note (JIT Warm-up): The first measurement may be higher due to V8 JIT compiler warm-up. To see the theoretical values, please run it 10 or more times. The stabilized measurement after warm-up is the true performance.

🔬 Verification Theory

❁EConventional (Arbitrary Color)

// Arbitrary unaligned color and alpha // Engine requires floating-point division fillStyle = "#E73A91" // Non-Mod32 globalAlpha = 0.2 // = 51/255 ↁEDivision occurs // ↁECPU: FDIV instruction (up to dozens of clocks)

An alpha value of 0.2 is internally 51/255, which is not divisible by 256. Skia executes division via SSE/FPU.

✁EOptimized (Mod32 + Power-of-2)

// Mod32 Boundary + Power-of-2 alpha // Engine can process with bitwise shifts only fillStyle = "#E04080" // Mod32 boundary globalAlpha = 0.25 // = 64/256 = >> 2 // ↁECPU: SHR instruction (1 clock)

An alpha value of 0.25 is 64/256, allowing the calculation to complete without division by simply shifting right by 2 bits (>> 2).
