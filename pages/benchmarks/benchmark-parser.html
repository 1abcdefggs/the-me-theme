JSON Parser Benchmark — Short Hex vs Long Hex

Short Hex (#F39 / #RRGGBBAA) vs Long Hex (#FF3399) — Parse Speed & Payload Size

When loading a theme, VS Code internally parses themes/*.json. By using Short Hex (#RGB / #RGBA), the JSON payload size (in bytes) is reduced, decreasing both the time taken for the V8 engine's JSON.parse() and memory usage. This benchmark demonstrates that difference.

⚠️ Measurement Note: JSON.parse() processing time is affected by V8's JIT and string caching. Please run it 10 or more times to see stabilized measurements. The difference in payload size (bytes) can be verified as a stable absolute value.

🔬 Verification Theory

❌ Long Hex (Standard 6-digit / 8-digit)

{ "editor.background": "#FF3399", "editor.foreground": "#FFFFFFCC", "focusBorder": "#E04080FF", // 7 to 11 bytes per color // 100,000 colors ≈ 700KB to 1.1MB JSON }

The standard format used by VS Code. Each color code string is long, increasing the theme JSON size and startup parsing load.

✅ Short Hex (3-digit / 4-digit Abbreviation)

{ "editor.background": "#F39", "editor.foreground": "#FFFC", "focusBorder": "#E48F", // 4 to 6 bytes per color (approx. 40% reduction) // 100,000 colors ≈ 400KB to 600KB JSON }

Only colors on the Mod17 boundary can be used. Character count is roughly halved, drastically reducing JSON load bytes and parsing time.
